# Сжатие и сохранение фактов

> Провенанс: независимо написано по утверждённому контракту и свидетельствам Task 2 без чтения или копирования `nickname76/russian-swears`; определения, примеры и формулировки созданы заново.

## Принцип

Сжатие — это сокращение объёма при полном сохранении всех обязательных фактов, отрицаний и порядка шагов. «Кратко» означает ограничение по длине, а не разрешение пропускать факты.

## Алгоритм сжатия

1. **Извлечь атомарные факты.** Каждое значение, ограничение, имя, команда, код ошибки — отдельный факт.
2. **Маркировать защищённые фрагменты.** Код, URL, SHA, порты, единицы измерения, точные ошибки — побайтовое воспроизведение.
3. **Маркировать отрицания.** Слова `не`, `никогда`, `только`, `кроме` и их синтаксические варианты — семантически защищены. Нельзя ослабить, инвертировать или опустить.
4. **Сократить связки и повторы.** Убрать вводные обороты, дублирующие пояснения, «как я уже упоминал», «стоит отметить, что».
5. **Объединить факты в плотные предложения.** Несколько фактов в одном предложении допустимы, если каждый факт остаётся распознаваемым.
6. **Финальная сверка.** Перед выдачей ответа сверить список извлечённых фактов с текстом ответа: каждый факт присутствует, ни одно отрицание не потеряно, порядок шагов совпадает.

## Пример технического сжатия

**Исходный запрос:** База слушает порт `5432`, таймаут `30 s`, три повтора, откат запрещён, владелец — SRE. Простой уже стоит денег, предыдущую работу нельзя выбрасывать.

**Плохое сжатие (потеря факта):** Порт `5432`, таймаут `30 s`. Откат запрещён, владелец — SRE.
— Потеряны: «три повтора», «предыдущую работу нельзя выбрасывать».

**Правильное сжатие:** Порт `5432`, таймаут `30 s`, три повтора. Откат запрещён, владелец — SRE; предыдущую работу не выбрасываем.
— Все шесть атомарных фактов на месте.

## Наблюдённые ошибки сжатия (из базовой линии)

| Класс ошибки | Пример | Почему это провал |
|---|---|---|
| Изменение формы факта | «три повтора» → «повторы — три» | Допустимая семантическая вариация, когда точные байты не требуются |
| Дублирование защищённого фрагмента | `не` появляется дважды при требовании ровно одного вхождения | Нарушение побайтовой точности |
| Ослабление отрицания | «не рекомендуется» вместо «запрещён» | Инверсия семантики ограничения |
| Лишнее вступление | «Давайте разберёмся с ситуацией...» перед ответом | Раздувание объёма без информационной нагрузки |

## Порядок шагов

Если запрос содержит пронумерованные шаги или явную последовательность действий, ответ сохраняет тот же порядок. Перестановка шагов — потеря факта о порядке, даже если содержание каждого шага верное.
