# Устройство

## Один источник смысла

`skills/koroche-blyat/SKILL.md` — единственное место, где живёт семантика.
Всё остальное либо выводится из него детерминированно, либо доставляет его до
модели.

```
skills/koroche-blyat/SKILL.md
        │
        │  scripts/generate_adapters.py  (SHA-256 по сырым байтам)
        ▼
adapters/generated/
        ├── always-on.md            полная политика
        ├── reminder.txt            одна строка напоминания
        └── claude-output-style.md  та же политика во фронтматтере Claude
        │
        │  scripts/install.py
        ▼
   Prime Agent          Codex CLI              Claude Code
   расширение           AGENTS.md + хук        стиль вывода + хук
```

Каждый сгенерированный файл несёт строку `canonical-sha256:` с суммой по
исходным байтам `SKILL.md`. Расхождение означает, что адаптеры собраны не из
того файла, и проверка `generate_adapters --check` это ловит.

## Два режима работы

**Скилл.** Папка `skills/koroche-blyat` кладётся в `~/.claude/skills/`. Модель
решает по описанию, подгружать её или нет. Просто, откатывается удалением
папки, но срабатывание не гарантировано и работает только в Claude Code.

**Скилл с адаптерами.** Установщик раскладывает сгенерированные артефакты по
каналам внедрения трёх хостов. Политика доезжает всегда, ценой установщика и
списка владения.

Разница ровно в этом: **детерминированность и охват хостов**.

## Каналы внедрения

| Хост | Куда пишется | Когда читается |
| --- | --- | --- |
| Prime Agent | `~/.prime/agent/extensions/koroche-blyat/` | событие `before_agent_start` на каждом запросе |
| Codex CLI | маркерный блок в `$CODEX_HOME/AGENTS.md` | при построении промпта сессии |
| Codex CLI | хук `UserPromptSubmit` | на каждом промпте, после ручного доверия |
| Claude Code | `output-styles/koroche-blyat.md` плюс `outputStyle` | при старте процесса |
| Claude Code | хук `UserPromptSubmit` | на каждом промпте |

Стиль вывода и список скиллов читаются при старте процесса — уже запущенная
сессия их не подхватит. Хуки читаются на каждом промпте и работают сразу.

## Владение и сохранность

Установщик владеет только тем, что создал сам. Границы владения записаны в
`${XDG_STATE_HOME}/koroche-blyat/manifest.json`.

Существующие файлы правятся точечно:

- **Markdown** — маркерным блоком `BEGIN/END KOROCHE-BLYAT MANAGED`; всё вне
  блока сохраняется байт в байт, включая переводы строк и отступы.
- **JSON** — разбором в конкретное синтаксическое дерево и заменой только
  нужного участка. Документ не сериализуется целиком, поэтому чужое
  форматирование, порядок ключей и escape-последовательности не меняются.

Применение транзакционное: снимок, журнал, резервные копии, запись во
временные файлы, атомарная замена, проверка результата и откат в обратном
порядке при любой ошибке. Многофайловая операция защищена откатом, но не
является атомарной на уровне файловой системы — это сказано прямо.

## Проверки

| Что | Чем |
| --- | --- |
| Адаптеры выведены из текущего `SKILL.md` | `scripts.generate_adapters --check` |
| Репозиторий пригоден к выпуску | `scripts.validate`, девять проверок |
| Поведение на зафиксированном корпусе | `evals/grade.py`, детерминированный грейдер |
| Сборка воспроизводима | две сборки под одним `SOURCE_DATE_EPOCH`, сверка `cmp` |
| Происхождение и лицензии | `scripts.check_upstreams`, офлайн и опционально по сети |

## Чего здесь нет

Ни сетевых вызовов во время работы, ни бинарников, ни телеметрии. Скилл — это
текст, который хост подмешивает в свой промпт. Установщик работает офлайн.
