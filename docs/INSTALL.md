# Установка koroche-blyat

Установка идёт из неизменяемого артефакта релиза. Скачивать удалённый скрипт
прямо в оболочку не нужно и не следует: артефакт проверяется по контрольной
сумме до того, как что-либо запустится.

## 1. Скачать артефакт и суммы

```sh
curl -fLO https://github.com/maksimryzhov614/koroche-blyat/releases/download/v1.0.0/koroche-blyat-1.0.0.tar.gz
curl -fLO https://github.com/maksimryzhov614/koroche-blyat/releases/download/v1.0.0/SHA256SUMS
```

Ссылка привязана к тегу `v1.0.0`, а не к ветке: содержимое по этому адресу не
меняется.

## 2. Проверить контрольную сумму

macOS:

```sh
shasum -a 256 -c SHA256SUMS
```

Linux:

```sh
sha256sum -c SHA256SUMS
```

Если проверка не прошла — остановитесь. Не распаковывайте архив.

## 3. Посмотреть, что внутри

```sh
tar -tzf koroche-blyat-1.0.0.tar.gz
```

Внутри только скилл, сгенерированные адаптеры, установщик и лицензии. Ни
бинарников, ни сетевых компонентов.

## 4. Распаковать

```sh
tar -xzf koroche-blyat-1.0.0.tar.gz
cd koroche-blyat-1.0.0
```

## 5. Сухой прогон

```sh
./install.sh --dry-run --all
```

Печатает детерминированный JSON с планом операций и **не создаёт ни одного
файла и каталога**, включая служебные. Значения ваших конфигов в вывод не
попадают.

Отдельные хосты:

```sh
./install.sh --dry-run --prime
./install.sh --dry-run --codex --claude
```

## 6. Установить

```sh
./install.sh --all
```

Без флагов хостов установщик обрабатывает доступные в порядке `prime`, `codex`,
`claude`. Явно указанный, но отсутствующий или слишком старый хост — это ошибка,
а не тихий пропуск.

Установка транзакционная: перед записью снимаются резервные копии и журнал, всё
проверяется после применения, а при любой ошибке изменения откатываются в
обратном порядке. Многофайловая операция защищена откатом, но не является
атомарной на уровне файловой системы.

## 7. Codex: доверить хуки вручную

Codex требует ручного подтверждения хуков — это его модель безопасности, обойти
её установщик не может и не пытается:

```sh
codex features enable hooks
codex
/hooks
```

Доверьте хук `koroche-blyat`. Пока он не доверен, Codex получает поведение из
глобального файла инструкций, и установщик сообщает состояние `DEGRADED`.

Если у вас `features.hooks=false`, установщик это значение **не перезаписывает**:
явное отключение пользователя уважается, а в план попадает ручное действие.

## 8. Проверить

Задайте любой обычный технический вопрос в свежем процессе хоста. Стиль должен
работать с первого хода без ключевой фразы.

Самоотчёт модели доказательством не считается: если нужна уверенность, смотрите
раздел о каналах внедрения в [COMPATIBILITY.md](COMPATIBILITY.md).

## Удаление

```sh
./install.sh --uninstall --all
```

Удаляются только записи из списка владения. Если вы правили файл, которым владеет
установщик, обычное удаление остановится и скажет об этом; `--force` снимает
владение с этого конкретного ресурса, не трогая остальное.

```sh
./install.sh --uninstall --prime
./install.sh --uninstall --force --claude
```

Удаление не требует, чтобы бинарник хоста всё ещё был установлен.

## Коды возврата

| Код | Значение |
| --- | --- |
| 0 | успех, отсутствие изменений или сухой прогон |
| 1 | сбой во время работы, изменения откачены |
| 2 | ошибка аргументов, предполётной проверки или владения |
| 3 | откат не завершён; пути журнала и резервных копий напечатаны |

Код 3 — единственный случай, когда нужно вмешательство руками: установщик
печатает точные пути журнала и резервных копий, они остаются на диске.
